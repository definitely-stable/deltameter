# M6-D8 — GF(2^64) scalar square specialization plan

Issue: #38. Parent: #19 / #14.  
Base: D7 merge `fda9f3fbe7abe32a0c5961571211cf3ab72eb74d`.  
Scope: private research only.

## Decision question

Does replacing only `gf64_mul(x, x)` inside the degree>=3 trace square/mod
path with a dedicated bit-equivalent scalar square produce a material
end-to-end reduction across the five D7 corpora?

## Candidate boundary

The candidate:

1. spreads each 32-bit half into even polynomial bit positions;
2. combines them into the 128-bit carryless square;
3. folds the high half with the frozen relation
   `x^64 = x^4 + x^3 + x + 1`;
4. performs one bounded carry fold;
5. uses only safe integer shifts, masks and XOR.

The D8 decoder calls the accepted D6 quadratic solver directly for degree two.
Generic GF multiplication remains in normalization, inversion, polynomial
reduction, GCD and division. No other decoder primitive is selected.

The D8-only module carries a byte-equivalent scalar `gf64_mul(x, x)` reference
for primitive differential testing. The accepted D6 support file remains byte-clean;
end-to-end equality against the real D6 decoder is the integration oracle.

## Correctness gates

- 64/64 polynomial basis vectors match the frozen scalar oracle.
- Edge values and at least 4096 deterministic full-width vectors match.
- D8 result/error equals accepted D6 at every k stage on all five corpora.
- Successful d<=8 recovery equals the exact oracle.
- d=9/10/16 reject.
- zero/high-bit/u64::MAX and invalid-limit/guard ordering remain unchanged.

## Performance evidence

Use the same five D7 deterministic 8192-key corpora and:

```text
d = 0,1,2,3,4,5,8,9,10,16
samples = 4 balanced AB/BA pairs per process
processes = 3 GitHub-hosted runs in one workflow
```

Control: accepted D6.  
Candidate: D8 square-only decoder.

Acceptance is based on paired end-to-end decoder timing, not the primitive
microbenchmark. Primitive timing may be retained only as diagnostic evidence.

## Frozen performance gate

This threshold is recorded before the first D8 performance run.

Primary d=8 gate:

- every corpus-level paired median reduction >= 5.0%;
- every per-process paired median for d=8 > 0%;
- aggregate paired median reduction across all five corpora >= 5.0%.

Guardrail:

- d=3/4/5: no corpus-level paired median regression below -2.0%;
- d=0/1/2 are noise/control cases and do not determine acceptance.

## Stop rule

- If correctness and all frozen performance gates pass: ACCEPT for private
  research and re-profile residual CPU before choosing anything else.
- Otherwise: NO-GO and stop algebraic micro-optimization. Move to maintained-state
  PinSketch vs direct exact vs rateless-style system comparison.

Production/public ExactSmallDelta remains NO-GO in either case.
