# Research foundation

This document records the conclusions that are strong enough to guide implementation. It also marks the points that are still research questions so that the code does not accidentally turn an asymptotic statement into a product guarantee.

## 1. Correct set-only model

For Boolean sets (A,B\subseteq[V]),

```text
x = 1_A - 1_B           over the integers
z = 1_A + 1_B mod 2     over GF(2)
```

and

```text
|A △ B| = F2(x) = ||z||_0.
```

The second identity is the important specialization for DeltaMeter. Generic (F_2) lower bounds remain useful context, but they are not automatically tight lower bounds for a GF(2)-linear, set-only Hamming-weight estimator.

## 2. Energy reference backend

For one hash/sign table with (B) buckets,

```text
c_b = sum_{i:h(i)=b} x_i * sigma_i
T   = sum_b c_b^2
```

under pairwise-uniform bucket collisions and suitable fourth-order sign independence,

```text
E[T]   = d
Var(T) = 2 d (d - 1) / B.
```

Therefore,

```text
P(|T-d| >= epsilon*d) <= 2 / (B*epsilon^2)
```

by Chebyshev. Repeating independent tables and taking the median gives an explicit finite-sample failure bound through the exact binomial tail.

This is intentionally conservative. It is a theorem-friendly baseline, not a claim that the chosen constants are optimal.

The research harness currently derives the following convenient power-of-two bucket families:

| epsilon | B |
|---:|---:|
| 0.05 | 8192 |
| 0.10 | 2048 |
| 0.20 | 512 |

For all three, the single-table bound is about 0.09765625. The minimum odd table counts used by the current harness are:

| target delta | R | median failure bound |
|---:|---:|---:|
| 1e-3 | 9 | 7.9800e-4 |
| 1e-6 | 23 | 3.6103e-7 |
| 1e-9 | 35 | 5.7078e-10 |

These numbers are regenerated by `research/energy_profiles.py`.

## 3. Parity / finite-field path

Finite-field PCSA is the most interesting fast direction because a set symmetric difference is naturally linear over GF(2), and update cost can touch one small state location.

The important restriction is that published asymptotic relative-error constants are **not** finite-sample coverage theorems at failure levels such as (10^{-6}) or (10^{-9}).

For the published GF(2) random-coefficient construction, a single level with (m) rows, level mass (r), and true difference (d) has exact first two moments:

```text
A = 1 - r/m
B = 1 - 2r/m

E[S]   = m/2 * (1 - A^d)

Var(S) = m/4 * [1 + (m-1)B^d - m A^(2d)].
```

The script `research/parity_level_moments.py` exists to keep those finite-(d) formulas executable and regression-testable.

What is still missing for a strict Parity capacity API:

- an all-(d), finite-(m) one-sided tail bound;
- clean treatment of level truncation;
- a proof that the concrete practical randomness model preserves the required tail;
- a useful width/power bound, not only coverage.

Until that exists, Parity is research/experimental for strict confidence claims.

## 4. Capacity contract

If an estimator has a proved two-sided event

```text
(1-epsilon)d <= d_hat <= (1+epsilon)d
```

with probability at least (1-delta), then

```text
C = ceil(d_hat / (1-epsilon))
```

satisfies

```text
P(C >= d) >= 1-delta.
```

On the same successful event,

```text
C/d <= (1+epsilon)/(1-epsilon)
```

up to integer rounding.

For epsilon 0.10, that successful-event multiplier is about 1.2222.

A direct one-sided upper confidence bound is also valid for safety, but safety alone does not imply a useful overprovision multiplier. The API must not conflate the two statements.

## 5. Small-d lane

Small (d) is important because relative error is awkward at (d=0,1,2,…). However, the bootstrap deliberately does **not** add Minisketch, BCH, IBLT, FFI, or another decoder yet.

Reason: the first implementation question is whether Energy and Parity already give the right product shape. Adding a recovery subsystem before that decision would enlarge the code and build surface prematurely.

Small-d exact recovery remains a candidate after the first Rust baselines and measurements.

## 6. Threat model

The first repository scope is the standard oblivious-input randomized-algorithm model: the data are not selected adaptively from observed sketch answers.

No secret-key mode is required for this initial contract.

Chosen-input-after-seed and adaptive-query robustness are explicitly out of scope for v0. If a real use case later needs them, they should become a separate design slice rather than silently adding cryptographic machinery to the default path.

## 7. Claims we may make now

Safe:

- set symmetric difference is a GF(2) Hamming-weight / (L_0) problem;
- Energy has the stated unbiasedness and variance under its stated randomness assumptions;
- median amplification gives an explicit conservative finite-sample profile;
- published finite-field PCSA is a strong fast-path candidate;
- Parity finite-sample (10^{-6})/(10^{-9}) capacity is not yet established.

Not safe yet:

- “DeltaMeter is optimal”;
- “Parity has proven 99.9999% coverage”;
- “CountSketch is categorically worse than sparse JL/SSE for this specialized task”;
- “a secret seed is required in the oblivious model”;
- “SIMD is required for acceptable performance”.
